## 1. 가입 — 5/5 통과

| 항목 | 방법 | 결과 |
|---|---|---|
| 정상 가입 | `POST /api/v1/users` | 201 + 토큰 |
| 이미 있는 닉네임 | 같은 닉네임으로 재가입 | 409 `USER_NICKNAME_DUPLICATED` |
| PIN 확인 불일치 | `pinConfirm`을 다르게 전송 | 400 |
| 닉네임 형식 오류 | 공백 / 특수문자 / 13자 | 모두 400 |
| PIN이 숫자 4자리 아님 | `12ab`, `123` | 모두 400 |

## 2. 로그인 / 5회 잠금 — 8/8 통과

| 항목 | 방법 | 결과 |
|---|---|---|
| 정상 로그인 | `POST /api/v1/users/login` | 200 + 토큰 |
| 틀린 PIN | 틀린 PIN으로 로그인 | 401 `USER_LOGIN_FAILED` |
| 없는 닉네임 | 존재하지 않는 닉네임 | 틀린 PIN과 같은 401 (계정 존재 여부 노출 없음) |
| 틀린 PIN 5번 → 잠금 | 5회 연속 틀린 PIN | 5번째까지 401, 이후 429 `USER_LOGIN_LOCKED` |
| 잠금 중 올바른 PIN | 잠금 직후 올바른 PIN | 429로 거부 |
| 실패 후 성공 시 초기화 | 4번 틀린 뒤 성공, 이후 4번 틀려도 안 잠김 | 통과 |
| 5분 뒤 로그인 | 잠금 5분 경과 후 로그인 | 200 |
| 로그아웃 후 토큰 삭제 | 로그아웃 후 F12 → Application → 저장소에서 토큰 확인 (프론트 화면) | 통과 (토큰 삭제됨) |

## 3. 내 정보 / 공개 설정 — 6/6 통과

| 항목 | 방법 | 결과 |
|---|---|---|
| 토큰 없이 조회 | `GET /api/v1/users/me` | 401 |
| 정상 조회 | 토큰으로 조회 | 닉네임, `isPublic` 기본 false |
| 공개 ON | `PATCH /api/v1/users/me` 후 재조회 | true 반영 |
| 공개 OFF | 같은 방식 | false 반영 |
| `isPublic` null / 문자열 | `null`, `"abc"` 전송 | 모두 400 |
| 새로고침 후 로그인 유지 | 로그인 상태에서 F5 (프론트 화면) | 통과 (로그인 유지) |

## 4. 담요 조각 — 10/10 통과

| 항목 | 방법 | 결과 |
|---|---|---|
| 로그인 상태 종료 시 자동 저장 | 승차권 발급 → 종료 (`POST /api/v1/tickets`, `/{id}/end`) | `savedToAccount: true` |
| 목록 최신순, 최대 9개 | `GET /api/v1/blanket-pieces` | 통과 |
| 조각 10개 이상일 때 최신 9개만 표시, 오래된 것은 삭제 안 됨 | 조각 11개 생성 후 목록 + 가장 오래된 조각 상세 조회 | 목록 9개, 오래된 조각 상세 200 |
| 조각 상세 앞·뒷면 | `GET /api/v1/blanket-pieces/{id}` | 도안, 번호, 기다림 이름, 열차 수, 종료 표식 |
| 남의 조각 상세 | 다른 계정 토큰으로 조회 | 403 `BLANKET_PIECE_FORBIDDEN` |
| 없는 조각 ID | 존재하지 않는 ID | 404 `BLANKET_PIECE_NOT_FOUND` |
| 비로그인 종료 후 계정으로 옮기기 | 비로그인 발급·종료 → `POST /api/v1/tickets/claim` | `savedToAccount: false` → 옮긴 뒤 계정에 저장 |
| 같은 조각 다시 옮기기 | claim 재요청 | 409 `TICKET_ALREADY_CLAIMED` |
| 열차 수가 기다린 시간에 맞게 계산 | 약 35초 뒤 종료, 응답의 열차 간격으로 기대값 계산 | ±1 이내 |
| 옮긴 뒤 열차 수가 종료 때와 같음 | 비로그인 종료 값과 claim 응답 값 비교 | 일치 |

## 5. 공개 카드 (STOMP) — 10/10 통과

프론트 대기실 화면(WebSocket 연동 후)에서 일반 창 + 시크릿 창 두 개로 같은 방에 입장해 승객을 눌러 확인했습니다. 서버 응답은 F12 → Network → Socket(`/ws`)의 `PASSENGER_CARD` 메시지로 확인했습니다.

| 항목 | 방법 | 결과 |
|---|---|---|
| 승객 탭 → `PASSENGER_CARD` 수신 | 두 창에서 같은 방 입장 후 탭 | 통과 |
| 공개 ON + 조각 있음 → PUBLIC (도안, 열차 수) | 메인 계정 | 통과 |
| 공개 OFF → PRIVATE | 보조 계정 | 통과 |
| 공개 ON + 조각 0개 → NO_PIECE | 보조 계정 공개 ON | 통과 |
| 비로그인 → GUEST | 비로그인 창 | 통과 |
| 닉네임·종료 표식 없음 | 화면과 F12 WS 메시지 확인 | 통과 |
| 9개 초과 시 최신 9개만 | 메인 계정 (조각 12개) | 통과 |
| 공개 설정 변경이 카드에 반영 | PATCH로 설정 변경 후 재탭 | 통과 |
| 방에 입장하지 않은 상태 → `REALTIME_NOT_JOINED` | 자동 테스트 `PassengerCardWebSocketTest` | 통과 (자동 테스트) |
| 방에 없는 번호 → `REALTIME_PASSENGER_NOT_FOUND` | 자동 테스트 `PassengerCardWebSocketTest` | 통과 (자동 테스트) |

위 두 에러 코드는 화면에서 재현하기 어려워 자동 테스트로 확인했습니다.

## 발견 사항

- **서버(user, blanket) 결함**: 없음
- **프론트에서 발견해 전달한 항목** (서버 문제 아님)
  - 대기실 화면이 WebSocket에 연결하지 않던 문제: 이후 연동되어 5번을 확인함
  - 로그아웃 시 검은 화면: 로그아웃 후 온보딩 화면으로 이동하게 해 해결됨을 확인함
  - 창 크기를 바꾼 뒤 "나" 캐릭터가 비정상적으로 크게 표시됨: 전달함, 해결 여부 미확인
  - 대기실 안내 문구 "열차는 30분에 한 번"이 서버 열차 간격(`TRAIN_INTERVAL_SECONDS`, 시연용으로 조정됨)과 다름: 전달함, 해결 여부 미확인

## 보안 관점 점검 근거

| 점검 | 근거 |
|---|---|
| 인증 없는 접근 차단 | 토큰 없이 `/users/me`, `/blanket-pieces` 호출 시 401 (QA 3번, 4번). 자동 테스트 `SecurityIntegrationTest` |
| 위조·만료 토큰 거부 | 만료 토큰, 다른 키로 서명한 토큰, 게스트 토큰으로 `/users/me` 모두 401 (`SecurityIntegrationTest`) |
| 남의 데이터 접근 차단 | 남의 담요 조각 403 (QA 4번, `BlanketServiceTest`), 남의 승차권 403 (`TicketControllerTest`) |
| 무차별 대입 방어 | PIN 5회 실패 시 5분 잠금, 잠금 중 올바른 PIN도 거부, 성공 시 초기화 (QA 2번, `UserTest`, `UserServiceTest`, `UserServiceLoginLockIntegrationTest`) |
| 계정 존재 여부 노출 방지 | 없는 닉네임과 틀린 PIN이 같은 401 응답 (QA 2번) |
| 입력 검증 | 닉네임·PIN·`isPublic` 형식 오류는 400 (QA 1번, 3번) |
| 비밀정보 보관 | PIN은 `PasswordEncoder`로 해시 저장, 운영 환경변수(JWT 키 등)는 `.env`로 주입하고 `.gitignore` 처리 |
| 쿼리 안전성 | JPQL·네이티브 쿼리는 모두 바인딩 파라미터 사용 |

## 알려진 한계

- PIN은 4자리 숫자라 경우의 수가 작습니다. 5회 잠금으로 보완합니다.
- JWT는 7일 유효이며 리프레시 토큰과 서버 측 로그아웃(토큰 무효화)이 없습니다.
- user·blanket 도메인에는 컨트롤러(HTTP) 단위 자동 테스트가 없어, HTTP 응답 검증은 이 문서의 수동 QA로 대신합니다.
- 방 상태는 서버 메모리에 있어 앱이 재시작되면 초기화됩니다.
- Swagger UI가 운영 서버에 노출되어 있습니다.

## 사용한 명령 (재현 방법)

[`QA_USER_BLANKET.ps1`](QA_USER_BLANKET.ps1)에 QA에 실제로 사용한 PowerShell 명령을 기록했습니다.

- 한 번에 돌리는 파일이 아니라 블록 단위로 순서대로 붙여넣어 실행한 명령 모음입니다. 각 줄 끝 주석이 기대 결과입니다.
- 닉네임(`QA********`, `QA***`)과 PIN(`"****"`)은 가려 두었으므로, 다시 실행하려면 본인 테스트 값으로 바꿔 넣으세요.
- 토큰은 응답에서 변수로 받아 쓰고 파일에는 기록하지 않았습니다.
- 테스트 계정과 담요 조각이 대상 DB에 남으므로 시연 직전에는 실행하지 마세요.
- 프론트 항목(로그아웃, 새로고침 유지, 5번 공개 카드)은 이 명령으로 확인할 수 없습니다.
